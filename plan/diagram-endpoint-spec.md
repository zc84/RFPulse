# Спецификация: эндпоинт генерации архитектурных диаграмм

**Назначение.** Публичный (внутренний Andersen) эндпоинт, который по структурированному запросу возвращает архитектурную/solution-диаграмму в брендовом стиле высокого качества (уровень RFPulse), сохраняя фактическую точность состава и связей.

**Статус.** Черновик v0.1 — для обсуждения перед реализацией.

---

## 1. Принцип проектирования: гибрид «структура + визуал»

OpenAI Images API рисует красиво, но управляется промптом и отдаёт растр — он **не гарантирует** корректность подписей, состава компонентов и стрелок. Для тендерного документа это неприемлемо: guardrail скилла — «изображать только то, что названо в предложении, ничего не выдумывать».

Поэтому эндпоинт разделяет ответственность на два слоя:

| Слой | Отвечает | Кто формирует |
|------|----------|---------------|
| **Структура** (узлы, группы, связи, подписи) | Фактическая точность | Клиент (Claude) присылает как JSON; сервер рендерит детерминированно |
| **Визуал** (стиль, фон, иконки, оформление) | Качество картинки | OpenAI Images API по бренд-промпту сервера |

Модели «неоткуда выдумывать»: состав задан жёстко, ей остаётся оформление.

### Рекомендуемый внутренний пайплайн сервера

1. Принять структурированный JSON.
2. Детерминированно отрендерить «скелет» диаграммы (Graphviz / SVG) — с чётким векторным текстом, боксами и стрелками.
3. Через Images API (`gpt-image-1`, режим редактирования изображения) наложить брендовый визуальный слой, используя скелет как reference/mask — **текст и связи не переписывать**.
4. Скомпоновать: векторный слой подписей поверх сгенерированного визуала, чтобы текст остался кристально чётким.
5. Вернуть PNG + метаданные.

> Если п.3–4 дают дрейф подписей — деградировать в «чистый детерминированный рендер с брендовой темой» и вернуть `warnings`, но не искажённую картинку.

## 2. Определение эндпоинта

```
POST /v1/diagrams/render
Content-Type: application/json
Authorization: Bearer <API_KEY>
```

- **Метод:** POST (тело — структурированный граф; GET не подходит).
- **Аутентификация:** `Authorization: Bearer` заголовок. → Из-за этого клиенту удобнее вызывать эндпоинт как **MCP-коннектор**, а не через сырой web_fetch (у него ограничения на POST/заголовки).
- **Идемпотентность:** одинаковый запрос при одинаковом `seed` должен давать воспроизводимый результат (кэшируемо по хешу тела).

## 3. Схема запроса (JSON)

```jsonc
{
  "diagram": {
    "title": "Solution architecture — <project>",
    "direction": "LR",              // LR | TB (слева-направо / сверху-вниз)
    "groups": [                     // логические кластеры (VPC, слои, зоны)
      {
        "id": "frontend",
        "label": "Frontend",
        "nodes": ["web", "mobile"]
      },
      {
        "id": "backend",
        "label": "Backend services",
        "nodes": ["api", "auth", "worker"]
      }
    ],
    "nodes": [
      {
        "id": "web",
        "label": "Web app",
        "tech": "react",            // ключ технологии для подбора иконки
        "icon": "auto"              // auto | <явный ключ иконки> | none
      },
      { "id": "api",  "label": "API gateway", "tech": "nginx" },
      { "id": "db",   "label": "PostgreSQL",  "tech": "postgresql" }
    ],
    "edges": [
      {
        "from": "web",
        "to": "api",
        "label": "HTTPS/REST",      // опционально
        "style": "solid"            // solid | dashed
      },
      { "from": "api", "to": "db", "label": "SQL" }
    ]
  },

  "style": {
    "brand": "andersen",            // тема бренда
    "palette": "default",           // при необходимости варианты
    "density": "balanced",          // compact | balanced | spacious
    "show_edge_labels": true,
    "fidelity": "high"              // high = задействовать Images-слой; strict = только детерминированный рендер
  },

  "render": {
    "format": "png",                // png (Images API отдаёт растр); svg = только детерминированный слой
    "width": 1920,
    "height": 1080,
    "scale": 2,                     // ретина
    "background": "transparent",    // transparent | white | brand
    "seed": 42                      // воспроизводимость
  }
}
```

### Правила валидации

- `edges[].from/to` обязаны ссылаться на существующие `nodes[].id` → иначе `422`.
- `groups[].nodes` — только существующие id; узел может входить максимум в одну группу.
- `nodes[].tech` неизвестен → иконка деградирует в нейтральный бокс с подписью (не подставлять чужой логотип).
- Пустой граф (`nodes` пуст) → `422`.

## 4. Схема ответа

**Успех — `200`:**

```jsonc
{
  "id": "diag_01H...",             // id рендера (для кэша/повторного скачивания)
  "format": "png",
  "encoding": "base64",            // base64 | url
  "image": "iVBORw0KGgoAAAANS...", // либо image_url при encoding=url
  "width": 1920,
  "height": 1080,
  "meta": {
    "fidelity_applied": "high",    // фактически применённый режим
    "nodes": 6,
    "edges": 5,
    "seed": 42
  },
  "warnings": [                    // не блокирующие проблемы
    "icon for tech 'legacy-esb' not found — rendered as labelled box"
  ]
}
```

- **Формат вывода:** `png` (Images API растровый). `svg` доступен только в режиме `fidelity: "strict"` (чисто детерминированный слой) — редактируемый и масштабируемый.
- **encoding:** `base64` для инлайна в документ; `url` (временная ссылка, TTL ≥ 15 мин) для больших файлов.
- **warnings** — обязательное поле: сюда идут все случаи деградации (недостающая иконка, откат fidelity), чтобы клиент понимал, где визуал не гарантирован.

**Ошибки:**

| Код | Когда | Тело |
|-----|-------|------|
| `400` | Некорректный JSON | `{ "error": "bad_request", "detail": "..." }` |
| `401` | Нет/неверный ключ | `{ "error": "unauthorized" }` |
| `422` | Валидный JSON, но невалидный граф (висячее ребро, пустой граф) | `{ "error": "invalid_graph", "detail": "edge references unknown node 'xyz'" }` |
| `429` | Лимит запросов | `{ "error": "rate_limited", "retry_after": 30 }` |
| `502` | Images API недоступен, а `fidelity: high` требовался | вернуть детерминированный PNG + `warnings`, а не падать (рекомендация) |
| `500` | Внутренняя ошибка рендера | `{ "error": "render_failed", "detail": "..." }` |

## 5. Guardrails (обязательны на стороне сервера)

- **Никогда не добавлять** узлы, связи или технологии, которых нет во входном JSON, даже если Images-модель «хочет» их дорисовать.
- Подписи узлов/рёбер в финальной картинке должны **дословно** совпадать с входными (векторный слой подписей поверх визуала — надёжнее всего).
- При любом расхождении визуала с входной структурой — откат в `strict` + `warnings`.
- Не подставлять логотип технологии, которого нет в каталоге, под похожий чужой бренд.

---

## 6. Обёртка MCP (рекомендуется вместо сырого HTTP)

Чтобы Claude вызывал эндпоинт как инструмент (POST + Bearer-ключ через web_fetch неудобны), оформить тонкий MCP-сервер с одним инструментом:

```
tool: render_architecture_diagram
input:  { diagram, style, render }   // = тело запроса из §3
output: { image (base64/url), format, meta, warnings }
```

Тогда клиент передаёт структуру напрямую и получает готовое изображение как результат инструмента — без ручного обращения к URL.

## 7. Пример сквозного вызова

**Запрос** (минимальный):

```json
{
  "diagram": {
    "title": "Solution architecture",
    "direction": "LR",
    "nodes": [
      { "id": "web", "label": "React SPA", "tech": "react" },
      { "id": "api", "label": "API Gateway", "tech": "nginx" },
      { "id": "db",  "label": "PostgreSQL", "tech": "postgresql" }
    ],
    "edges": [
      { "from": "web", "to": "api", "label": "HTTPS" },
      { "from": "api", "to": "db",  "label": "SQL" }
    ]
  },
  "style":  { "brand": "andersen", "fidelity": "high" },
  "render": { "format": "png", "scale": 2, "seed": 7 }
}
```

**Ответ** — `200` с base64-PNG, `meta.fidelity_applied: "high"`, пустой `warnings`.

## 8. Открытые решения (нужно твоё слово)

1. **Хостинг/доступ:** внутренний сервис за VPN или публичный эндпоинт с ключом? Влияет на приватность (в запросе уходят стек и компоненты тендера).
2. **strict vs high по умолчанию:** какой режим fidelity считать дефолтным, если клиент не указал?
3. **Каталог иконок:** брать из существующего набора RFPulse или переиспользовать native-иконки `diagrams`?
4. **SVG-выход:** нужен ли он вообще, или PNG достаточно для вставки в предложения?
5. **Лимиты:** ожидаемый rate limit и максимальный размер графа (число узлов/рёбер).
